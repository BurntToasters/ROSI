# Renderer API as an ES module: failure modes (written before the change)

Scope: the API object built in `src/tauri-bridge.ts` moves to `src/api.ts` and is exported as `api`. It is no longer `window.api`. Renderer callers import it. The E2E hook exposes the same object as `window.__ROSI_E2E__.api`. The baseline is 73 passing vitest cases and the DOM check artifact `e2e/artifacts/round3-renderer/renderer-dom-checks.json` as it was before the change.

## Required behavior

- `src/api.ts` exports `api` (typed `RosiRendererApi`) and `waitForPrepareForCloseListener`. The method names, arguments, and result shapes stay as they are.
- `src/tauri-bridge.ts` is deleted. Nothing else remains in it.
- The `RosiRendererApi` interface moves out of `src/renderer-globals.d.ts` into `src/api.ts`. The `api` member is removed from `Window`.
- `src/e2e-hook.ts` sets `window.__ROSI_E2E__.api = api` inside the `VITE_ROSI_E2E === '1'` branch, in the same assignment as `ready: true`.
- Every e2e reference reads `window.__ROSI_E2E__.api` and uses optional chaining before the hook has run.

## Proof

1. `npm run typecheck`, `npm test`, `npm run lint`, `npm run validate:no-em-dash`, and prettier on changed files.
2. `node scripts/e2e/runners/renderer-dom-checks.js`, compared with the baseline artifact.
3. `git grep -n "window\.api" -- src e2e ':!e2e/artifacts'`, expecting no output apart from explained prose.
4. Default `npx vite build`, then grep the built JS for `window.api` and `__ROSI_E2E__`.
5. Full E2E gate through the shared build lock, with no `--group`.
