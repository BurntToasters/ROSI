# Renderer modules to ES imports: failure modes (written before the change)

Scope: the eight IIFEs in `src/modules/` (icons, ui, downloads, activity, queue, settings, updates, dock) move from `window.rosiModules` registration to plain ES modules with named exports. `src/engine/core.ts` and the engine callers import them directly.

## How the conversion could fail

| #   | Failure                                                              | Why it could happen here                                                                                                                                                   | Required behavior                                                                                                                                | How it is proven                                                                                                                                                                    |
| --- | -------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Init order changes                                                   | `icons.ts` runs `initializeIcons()` at evaluation time, swapping `span[data-icon]` placeholders before the window shows. Before, it ran before `rosiEngine` evaluated.     | `icons` evaluates before the engine body, as the first renderer import after `tauri-bridge`. `main.ts` keeps that one side-effect import.        | Renderer DOM checks and the E2E gate (icons on the first paint). Code review of `main.ts` import order.                                                                             |
| 2   | A load-time side effect is lost or runs twice                        | Only `icons.ts` has one. The other seven only define functions and register them. A re-import through two paths could re-run it.                                           | `initializeIcons()` runs exactly once per document. No other module does DOM work at evaluation.                                                 | Vitest DOM suite resets modules per test (`vi.resetModules`) and checks the icons output. Renderer DOM checks load each file once through the cache.                                |
| 3   | Circular import leaves a binding undefined                           | `ui` needs `icons` and `dock`. `core` needs the modules. A module importing `engine/*` would close a loop.                                                                 | Module files import only other modules or nothing. No module imports `engine/*`.                                                                 | Grep for `from '../engine` and `from './engine` inside `src/modules/`. Typecheck. Engine evaluation would throw on an undefined call at startup, so the DOM suite and E2E catch it. |
| 4   | DOM test or renderer DOM checks still depend on `window.rosiModules` | `rosiEngine.dom.test.ts` and `renderer-dom-checks/*.cjs` load modules by side effect and read the registry (`w.rosiModules.ui.closeSidebar()`).                            | Tests get modules by import, or through the loader cache. No reads or writes of the global remain.                                               | `grep -rn rosiModules src e2e` returns nothing (excluding artifacts). Assertions in `rosiEngine.dom.test.ts` are unchanged.                                                         |
| 5   | A module loses state shared between callers                          | `dock` keeps `state`, `onChange`, and `bound` at module level. `ui` keeps `sidebarTrapHandler`, `previousSidebarFocus`. The old registry gave one instance per document.   | Module state stays module-level, so there is still one dock state per document. Per-panel state stays in the `initActivityPanel` closure.        | Dock E2E scenarios (tab selection, collapse, console tab) and the DOM suite's dock checks.                                                                                          |
| 6   | `ui.updateConsoleVisibility` fallback is dropped                     | The old code fell back to `#dockTabConsole.hidden` when `dock` was absent. Dock is now always present.                                                                     | In the app, `dock` is always present, so the behavior is the same. The fallback branch is removed.                                               | `rendererModules.test.ts` ui cases still pass with dock loaded. Console E2E scenario.                                                                                               |
| 7   | Stale test harness hides a real break                                | `rendererModules.test.ts` evaluates module source with `eval`, which cannot run `import` statements. A harness that silently returns `{}` would pass nothing.              | The harness imports each module and fails on a missing export. Assertions are unchanged.                                                         | Vitest run must show the same number of passing cases in the module suite.                                                                                                          |
| 8   | E2E specs still read `window.rosiModules`                            | `e2e/specs/main.spec.js`, `e2e/platform-probes/probes.spec.js`, and `e2e/v5-fixes/ui-polish/ui-polish-focus.spec.js` call `window.rosiModules.dock.selectTab` and similar. | Known blocker. These specs are outside this piece's edit list. They must be migrated (or their owner must approve) before the E2E gate can pass. | E2E run output names each failing spec. Reported to the caller.                                                                                                                     |

## Required behavior

- Each module exports the same names the engine used. Callers update their imports. No `window.rosiModules` in `src/` or in the renderer DOM checks.
- The `window.rosiModules` declaration and every `Rosi*Module` contract type are removed from `src/renderer-globals.d.ts`. Data types still used by the engine stay.
- `main.ts` keeps `tauri-bridge` first, then the `icons` side-effect import, then `rosiEngine`, as before.
- `window.api` is untouched.

## Proof

1. `npm run typecheck`, `npm test`, `npm run lint`, `npm run validate:no-em-dash`, and prettier on changed files.
2. Renderer DOM checks runner (`scripts/e2e/runners/renderer-dom-checks.js`) against the loader, which now resolves `?raw` SVG imports.
3. `grep -rn rosiModules src e2e` with the excluded artifacts directory.
4. E2E gate through the shared build lock, groups `ui-polish,settings`, with the failing specs from failure mode 8 reported as-is.
