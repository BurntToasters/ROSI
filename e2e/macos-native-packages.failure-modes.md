# macOS native package failure modes

This inventory was written before implementation. `scripts/e2e-macos-native-packages.mjs`
will exercise the packaging and release-asset rules with isolated fixtures and
write repeatable JSON evidence. macOS signing, notarization, DMG mounting, and
native Mach-O inspection remain platform acceptance checks for a macOS release
machine.

| ID    | Failure mode                                                                                                                              | Required result                                                                                                                                                                                         |
| ----- | ----------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| MNP01 | An arm64 package is built from a universal or x86_64 app, or vice versa.                                                                  | Reject the bundle because the ROSI host executable and native FFmpeg/ffprobe sidecars do not contain exactly the requested architecture.                                                                |
| MNP02 | A valid native bundle contains upstream universal2 yt-dlp.                                                                                | Accept it when it includes the requested architecture; do not require yt-dlp to be thin.                                                                                                                |
| MNP03 | Any app or sidecar requires a macOS version above the configured minimum.                                                                 | Reject the package and identify the offending executable and slice.                                                                                                                                     |
| MNP04 | The app or sidecar is ad-hoc signed, signed by another team, has mismatched entitlements, or is not notarized/stapled.                    | Reject before writing the ZIP; preserve Developer ID, team, entitlement, and staple checks for the requested slice. Fixture evidence checks these gates remain wired; signed acceptance requires macOS. |
| MNP05 | The plist marketing version or bundle version does not match the release config.                                                          | Reject the package.                                                                                                                                                                                     |
| MNP06 | The native DMG/ZIP receives a generic or colliding filename.                                                                              | Emit the unique `ROSI-MacOS-arm64`, `ROSI-MacOS-x64`, or `ROSI-MacOS-universal` basename and keep each architecture distinct through collection, sidecars, and checksums.                               |
| MNP07 | A stale or duplicate architecture package is present alongside the new one.                                                               | Require current-session outputs, preserve architecture names, and fail on ambiguous same-name DMGs/ZIPs instead of silently choosing one.                                                               |
| MNP08 | A ZIP is missing, empty, or misnamed after packaging.                                                                                     | Fail E2E/release verification; require both native DMGs and ZIPs in the draft.                                                                                                                          |
| MNP09 | GPG signing sees native package names.                                                                                                    | Sign each DMG and ZIP once; do not normalize native names back to universal or collide with the universal signatures.                                                                                   |
| MNP10 | SHA256SUMS files omit a native package, duplicate it, or use an architecture-inaccurate target key.                                       | Generate deterministic checksum target lists covering each package and verify the uploaded checksum/signature assets against those names.                                                               |
| MNP11 | An updater manifest resolves a compact archive to the wrong architecture, or a native installer is mistaken for an updater archive.       | Keep legacy universal app feeds intact; preserve per-architecture zstd feeds and validate the updater archive against the host architecture.                                                            |
| MNP12 | The macOS release rebuilds the same native app separately for installer and compact updater packaging.                                    | Build each per-architecture app once with its DMG and updater archive, then feed that app/archive to both packagers.                                                                                    |
| MNP13 | A build or release command runs on Windows and pretends native macOS acceptance succeeded.                                                | The fixture E2E reports static pipeline evidence only and clearly records native platform checks as blocked.                                                                                            |
| MNP14 | The updater's universal fallback, Rosetta native-arm64 selection, or missing-architecture fallback changes while adding native downloads. | Retain existing updater routing behavior and the universal release/update artifacts.                                                                                                                    |
| MNP15 | `--require-real-builds` runs off macOS or any of the six current package files is missing.                                                | Fail the command; fixture helpers must never satisfy a real release gate.                                                                                                                               |
| MNP16 | A native DMG or ZIP is as large as or larger than its universal counterpart, or a payload hash cannot be recorded.                        | Fail for that package and report file size plus SHA-256 for every package and source bundle.                                                                                                            |
| MNP17 | A ZIP is truncated, changes the app tree, loses its Developer ID signature, or loses its staple.                                          | Extract it with macOS `ditto`, compare the complete bundle tree and executable hashes to the source app, then validate code signature and notarization staple.                                          |
| MNP18 | A DMG cannot mount, contains no single `ROSI.app`, has the wrong target architecture, or fails signature/staple validation.               | Attach read-only, require exactly one app, reuse target-aware bundle verification, and detach every mounted image in `finally`, including on failure.                                                   |
| MNP19 | A package or source bundle predates the current release build, or its version differs from `package.json`/`tauri.conf.json`.              | Fail real acceptance rather than using stale or mismatched local artifacts.                                                                                                                             |
| MNP20 | A mounted volume remains after verification fails.                                                                                        | Detach every image attached by this E2E run in `finally` and report cleanup failures without hiding the original verification error.                                                                    |

Fixture mode is cross-platform pipeline evidence and does not prove that a
package was built, signed, stapled, mounted, or smaller. `--require-real-builds`
must run after the three real builds on macOS, verify every package and mounted
DMG, and write actual hashes, sizes, and native acceptance results. The release
chain uses this strict mode.
